# 02. バトル設計

## 2.1 フィールド

- **グリッド**: 16 × 9 マス（1 マス = 64px、描画解像度 1024 × 576 を基準に拡大縮小）
- **敵の経路**: ステージごとに定義された固定ルート（1〜3 レーン）。分岐・合流あり。
  経路はウェイポイント配列で持ち、敵はその上を線形補間で進む（マス単位の探索は行わない）。
- **配置マス**: 経路外のマスのうち、ステージデータで `placeable: true` のもの。
  マスには種別があり、配置ボーナスが乗る。

| マス種別 | 効果 |
|---|---|
| ステージ（本舞台） | 攻撃力 +10%（メイン花道の近く） |
| 花道 | 射程 +15% |
| 客席サイド | 声援獲得 +20%、攻撃力 -10% |
| モニター前 | ヴィジュアル系スキルの効果時間 +25% |

- **ゴール**: 経路終端の「センターステージ」。敵が到達すると観客ゲージが減る。

## 2.2 敗北条件 —— 観客ゲージ

- HP に相当するのが **観客ゲージ（Audience）**。初期値 100。
- 敵 1 体がセンターステージに到達すると、その敵の `leak` 値だけ減少（雑魚 1、大型 5、ボス 20）。
- 0 になった時点でライブ中断 = 敗北。
- 観客ゲージは声援の自然回復量に比例して効く（後述）ため、「漏らすほど後半が苦しくなる」設計。

## 2.3 リソース

### 声援（Cheer）— 配置・強化に使う主通貨

| 入手 | 量 |
|---|---|
| 開始時 | 150 |
| 自然回復 | `2.0 + 0.04 × 観客ゲージ` /秒（満タン時 6.0/秒） |
| 敵撃破 | 敵ごとの `bounty`（雑魚 6 / 中型 14 / 大型 30 / ボス 120） |
| ウェーブ完全防衛（1 体も通さない） | +25 |

### ボルテージ（Voltage）— スペシャル発動ゲージ

- 0〜100。100 で **スペシャルライブ** が発動可能になる（自動発動 / 手動温存を選択可）。
- 蓄積源:
  - 与ダメージ 100 につき +0.4
  - 敵撃破 +1.5（大型 +6、ボス +25）
  - コール成功（後述）+3
  - サビウェーブ中は蓄積量 **×1.5**
- 発動すると 0 にリセットし、8 秒間の演出フェーズへ:
  - 全メンバーの攻撃速度 +50%、攻撃力 +30%
  - 画面全体に初期ダメージ（センターの `special` 倍率に依存）
  - 敵の移動速度 -30%
- スペシャル中はボルテージが溜まらない（無限ループ防止）。

## 2.4 ウェーブ = 楽曲構成

1 ステージ = 1 楽曲。楽曲は **セクション** に分割され、これがウェーブに対応する。

| セクション | ウェーブ性質 | 補正 |
|---|---|---|
| イントロ | 準備時間 20 秒、敵なし | 声援自然回復 ×1.5 |
| A メロ | 雑魚中心 | なし |
| B メロ | 中型・特殊が混ざる | 敵の移動速度 ×1.1 |
| サビ | 大量 + 高密度 | ボルテージ蓄積 ×1.5、敵 HP ×1.15 |
| 間奏 | 敵なし、10 秒 | セットリスト選択（◆） |
| 大サビ | 最終ウェーブ、ボスを含む | 全補正 ×1.25 |

### セットリスト選択タイミング（◆）

間奏は 1 曲に 1 回しかないため、それだけではカード選択回数が足りない。
**敵の湧きが途切れるセクション境界**を選択ポイント（◆）とし、楽曲データの `cardPicks` に明示する。

原則として次の 4 箇所に置き、1 ライブあたり **4〜5 回** の選択が発生する:

1. イントロ終了時
2. 各サビの終了時（曲中に 2〜3 回ある）
3. 間奏
4. 大サビ直前（直前のサビ終了と重なる場合は 1 回に統合）

◆ の位置は楽曲ごとに [04.4](./04-content.md#44-楽曲) の構成表に記載する。
選択中はシミュレーションを停止する（時間制限なし）。

- セクション遷移は **BPM クロック** に同期する。曲の 1 小節 = 内部の `beat` イベント。
- 敵のスポーンタイミングも小節単位で定義するため、「リズムに乗って敵が湧く」画になる。
- 音楽が無効（ミュート）でも内部クロックは動くので、ゲームプレイは音に依存しない。

## 2.5 3 系統と属性相性

### メンバーの系統（Type）

| 系統 | 役割 | 攻撃の性質 | 代表挙動 |
|---|---|---|---|
| **歌 / Vocal** | 範囲・持続 DPS | 経路に沿って広がる音波、貫通 | リング状の範囲攻撃を一定間隔で放つ |
| **ダンス / Dance** | 単体・瞬間火力・機動 | 高速単体、ノックバック、移動阻害 | 最も進んだ敵に高速連撃 |
| **ヴィジュアル / Visual** | 妨害・支援 | デバフ、魅了、味方バフ | 範囲内の敵に減速／防御低下、味方に攻撃力バフ |

### 敵の属性（Attribute）

| 属性 | イメージ | 弱点 |
|---|---|---|
| 静寂 / Silence | 無関心、聞く耳を持たない | 歌 |
| 喧噪 / Noise | 野次、騒音 | ダンス |
| 虚飾 / Glare | 偽物の輝き、まがい物 | ヴィジュアル |

### 相性倍率テーブル

|  | vs 静寂 | vs 喧噪 | vs 虚飾 |
|---|---|---|---|
| 歌 | **1.3** | 1.0 | 0.8 |
| ダンス | 0.8 | **1.3** | 1.0 |
| ヴィジュアル | 1.0 | 0.8 | **1.3** |

3 すくみが循環するため、どの系統も「腐る相手」と「刺さる相手」を必ず持つ。
編成画面でステージの属性構成比を事前開示し、編成判断の材料にする。

## 2.6 ダメージ計算

```
最終ダメージ = ATK
             × スキル倍率            (skillMul: 0.5 〜 3.0)
             × 属性相性              (typeMul: 0.8 / 1.0 / 1.3)
             × (1 + Σ攻撃力バフ - Σ攻撃力デバフ)
             × クリティカル倍率       (crit時のみ: 1.5 + critDmgBonus)
             × 防御軽減              (100 / (100 + DEF_eff))
             × 被ダメージ補正        (1 + 敵の脆弱度)
```

- `DEF_eff = max(0, 敵DEF × (1 - 防御無視率) - 防御低下量)`
- 防御 100 でダメージ半減、200 で 1/3。敵 DEF レンジは 0〜240。
- クリティカル率は上限 100%、超過分は 1% ごとにクリティカルダメージ +0.5% に変換。
- ダメージ表示は整数に丸め、内部計算は浮動小数のまま保持する。

### DPS の目安（Lv1 / 相性等倍 / DEF0）

| 系統 | ATK | 攻撃間隔 | skillMul | 単体 DPS | 想定同時ヒット数 | 実効 DPS |
|---|---|---|---|---|---|---|
| 歌 | 90 | 1.6s | 0.9 | 51 | 3.0 | 152 |
| ダンス | 130 | 0.7s | 0.8 | 149 | 1.0 | 149 |
| ヴィジュアル | 60 | 1.2s | 0.7 | 35 | 2.0 | 70 + 支援価値 |

ヴィジュアルは素の DPS を意図的に低くし、デバフ（防御 -30%、被ダメ +20%）で
パーティ全体の火力に貢献する形で価値を出す。

## 2.7 ターゲティング

各ポジションは以下から選択（配置後いつでも切替可、コスト 0）。

| モード | 説明 |
|---|---|
| 先頭 (default) | 射程内で最もゴールに近い敵 |
| 最後尾 | 射程内で最もゴールから遠い敵 |
| 最大 HP | 射程内で現在 HP が最大の敵 |
| 最小 HP | とどめ用 |
| 弱点 | 射程内で自分の系統が有利な敵を優先、なければ先頭 |

範囲攻撃はターゲットを中心に判定する。デフォルトを「先頭」に、
慣れたプレイヤーが「弱点」で最適化できる余地を残す。

## 2.8 状態異常・バフ

| 名称 | 効果 | 重複 |
|---|---|---|
| 減速 (Slow) | 移動速度 -X% | 最大値のみ適用 |
| 魅了 (Charm) | X 秒間、経路を逆走 | 上書き（時間更新） |
| スタン (Stun) | X 秒間、停止 | 上書き。ボスは耐性 70% |
| 防御低下 (Break) | DEF -X | 加算、上限 -80% |
| 脆弱 (Fragile) | 被ダメージ +X% | 加算、上限 +100% |
| 熱狂 (Fever) | 味方の攻撃速度 +X% | 加算、上限 +150% |
| 継続ダメージ (Echo) | 毎秒 X ダメージ、系統相性を適用 | 独立に最大 5 スタック |

- すべて `StatusEffect { id, kind, value, remainingMs, sourceId, stackRule }` で統一表現。
- ボス級は `resist: { stun: 0.7, charm: 1.0, slow: 0.3 }` を持ち、`効果時間 × (1 - resist)`。
  resist 1.0 は完全無効。

## 2.9 コール & レスポンス（アクティブ操作）

タワーディフェンスは基本的に見ているだけになりがちなので、**任意参加**の能動操作を入れる。

- サビ中、画面下部にコールタイミングのマーカーが流れる（BPM 同期、1 小節に 1 回）。
- タイミング良くクリック / スペースキー:
  - Perfect (±80ms): ボルテージ +3、全体攻撃力 +5%（3 秒）
  - Good (±160ms): ボルテージ +1.5
  - Miss: ペナルティなし
- **押さなくてもクリアできる** 難易度に調整する。上手い人が 10〜15% 得をする程度。
- オプションで完全 OFF 可能（アクセシビリティ）。

## 2.10 敵のスケーリング

★スケーリングは HP だけに掛けない。HP・防御・出現密度の 3 軸に分散させることで、
「HP だけが膨らんで殴り合いが間延びする」状態を避ける。

```
HP(wave, stage, star)  = baseHP × (1 + 0.18 × (wave - 1)) × stage.hpMul × 1.35 ^ (star - 1)
DEF(star)              = baseDEF + 18 × (star - 1)
出現数(star)            = baseCount × 1.08 ^ (star - 1)

報酬(star)              = base × 1.15 ^ (star - 1)
```

### 要求戦力（★ごとに必要なプレイヤー側の総合火力）

```
要求戦力(★) = HP係数 × 防御係数 × 密度係数
```

| 係数 | ★10 での値 | 内訳 |
|---|---|---|
| HP 係数 | 14.9× | `1.35^9` |
| 防御係数 | 約 2.0× | 基準敵 DEF 60 → 222。軽減率 `100/(100+DEF)` が 0.625 → 0.311 |
| 密度係数 | 2.0× | `1.08^9` |
| **合計** | **約 59.9×** | ★1 比 |

この **約 60 倍** が、[03. 強化要素](./03-progression.md#c-バランス設計の指針) で定めた
「全系統フル強化時の総合戦力 60 倍」と一致する。★10 を最終強化状態のクリア率 40〜70% の
壁として設計し、両者がずれていないことをヘッドレスシミュレータで継続検証する。

- ★は 1〜10。★7 以降は追加ルール（ボス 2 体同時、特定系統の攻撃力 -20% など）を付与し、
  数値インフレだけで難しくしない。追加ルールの難度寄与は上式に含まれないため、
  **★7〜10 の 3 係数は `balance.json` で個別に上書き**し、
  シミュレータで計測した実効要求戦力が 60 倍のカーブから外れないよう調整する
  （追加ルールを入れた分だけ係数を下げる、という運用）。

## 2.11 決定性

- シミュレーションは **固定タイムステップ 1/60 秒**。描画は補間。
- 乱数はすべて seed 付き PRNG（mulberry32）経由。`Math.random()` の直接使用を lint で禁止。
- 同じ seed + 同じ入力列 → 同じ結果。これにより:
  - リプレイ / ゴーストの保存が軽量（入力列のみ）
  - ヘッドレスのバランスシミュレータで 1 万回試行を回せる（[05](./05-architecture.md) 参照）
