# 07. 開発ロードマップ

各マイルストーンは「動くものが増える」単位で切る。受け入れ条件を満たさないうちは次に進まない。

## M0 — 基盤（1 週間相当）

- Vite + TypeScript(strict) + Vitest + ESLint の雛形
- `core/`（固定タイムステップループ、seeded RNG、EventBus、Vec2）
- Canvas レンダラの土台（レイヤ、カメラ、スプライト仮描画）
- データローダ + Zod スキーマ + `npm run validate:data`
- GitHub Pages への配信を有効化（`vite.config.ts` の `base`、`package-lock.json` のコミット、
  リポジトリ設定の Pages Source を GitHub Actions に変更）。
  ワークフロー `.github/workflows/deploy.yml` は追加済みで、`package.json` が入った時点で動き出す

**受け入れ条件**: 空のステージが 60fps で描画され、`Math.random()` の使用が lint で落ちる。
`main` への push で `https://masaspc.github.io/IdolDiffence/` が更新される。

## M1 — バトルの最小成立（プレイアブル最小）

- ステージ 1（1 レーン、8 ウェーブ）、敵 2 種（e_walker / e_runner）
- アイドル 3 人（各系統 1 人）、配置・声援・観客ゲージ
- ターゲティング（先頭のみ）、ダメージ式、属性相性
- 勝敗判定とリザルト画面（報酬なし）

**受け入れ条件**: ステージ 1 を最初から最後まで遊べて、勝ちも負けもする。

## M2 — 強化 P0（本作の中核が立つ）

- ①ポジション強化（Lv1〜3）
- **②覚醒分岐（Lv3 時の A/B 択）**
- ③セットリスト（3 択カード、コモン / レア 20 種）
- ⑦アイドルレベル（1〜30）
- **簡易ボルテージ / スペシャル**（ゲージ・サビ 1.5 倍・ボタン発動・8 秒の全体バフまで。
  カットインとパーティクルは M5）
- セーブ / ロード + マイグレーション基盤

衣装（⑨）は M3（実際には M3-2b）へ後ろ倒しした。理由は [03 F](./03-progression.md#mvp-から衣装を外し覚醒分岐を入れた理由)。

加えて、判断のための**計測**をここで入れる（M3 の本格 CI 検証より前倒し）:

- 固定 seed のリプレイランナー（UI・CI なしの簡易版でよい）
  → `src/sim/autoplay.ts`（ヘッドレス駆動）、`scripts/probe.ts`（条件別の一覧）、
    `scripts/sweep-difficulty.ts`（難度パラメータの探索）
- ローカルのイベントログ + リザルトからの JSON エクスポート
  （seed / 編成 / 配置と時刻 / 強化の対象と時刻 / 提示された 3 枚と選択 / 覚醒 A・B /
  スペシャル発動時刻 / 敗北ウェーブ / 残観客 / 系統別・キャラ別ダメージ / 未使用声援 / 即リトライしたか）

**受け入れ条件**: 「負ける → 育てる → 勝つ」のループが 3 ステージで成立する。
ここで面白くなければ、以降の系統追加は問題を解決しない。**最重要の判断ポイント**。

判定は感想ではなく、以下を満たすかで行う:

| 観点 | 満たすべき状態 |
|---|---|
| 敗因の理解 | 負けた直後に「なぜ負けたか」を言語化できる |
| 再挑戦意欲 | 敗北後の即リトライ率が高い |
| 選択の意味 | カード選択率が特定 1 枚に極端集中していない |
| ビルド多様性 | 同じステージを異なる覚醒・カード構成でクリアできる |
| 育成の効き方 | 1 段階の育成で勝率が上がるが、**100% にはならない** |

最後の 1 行が肝心。「育てれば必ず勝つ」だけなら、それはゲームループではなく
待ち時間つきの数値ゲートでしかない。同一 seed・同一編成で
「無育成 / レベルのみ / レベル + 適切なカード / レベル + 不適切なカード」を比較し、
**育成で勝ちやすくなるが、判断の差も残る**ことを確認する。

## M3 — 深さ（強化 P1 + コンテンツ拡張）

量が多いので 2 本に分けて進める。**M3-1 が土台**（誰を出すか）で、
M3-2 が**その上の伸ばし方**（どう強くするか）。順序を逆にすると、
フォーメーションや衣装を検証する相手（キャラとステージ）が足りない。

### M3-1 — コンテンツ拡張と編成 ✅

- アイドル 9 人（固有スキルと覚醒 A/B）、敵 9 種（特性つき）、ステージ 1〜7、楽曲 5 曲
- ⑤センター（編成画面で固定選択）と **出撃 5 人の編成**、ステージクリアによる加入
- 敵の特性: 回復オーラ / 攻撃速度デバフ / 前面シールド / 分裂
- 新しい挙動: 貫通線、防御無視、処刑倍率、ノックバック、魅了・スタン、脆弱、味方オーラ
- ヘッドレスバランスシミュレータと CI 検証（`src/balance/balance.test.ts`）

### M3-2 — 強化 P1 ✅

- ④フォーメーション（隣接・同系統・同ユニット・一列・センター護衛の 5 種）
- ⑧才能ボード（3 ブランチ × 12 ノード、キーストーン排他、資金で振り直し）
- ①ポジション強化を **3 段階 → 6 段階**へ拡張。②覚醒はもう一方が Lv6 で開く
- ⑦-2 進化（初期メンバー 3 人の (Ray) バージョン）
- ドット絵を 32×32 → 48×48 に作り直し、進化後の絵も持てるようにした
- スペシャルライブの本演出（カットイン、画面効果）

**受け入れ条件**: 同じステージを異なる編成・ビルドでクリアでき、
シミュレータ上でクリア率が想定レンジに収まる。

**やったこと / 分かったこと**:

- ポジション強化を 6 段階にしたら、参照盤面が余剰声援を吸うようになり
  **S2〜S5・S7 が Lv1 で完走**してしまった。`hpMul` を全面的に振り直している
  （[04 `hpMul` の表](./04-content.md#hpmul-は想定する盤面の完成度を表す)）。
  強化を足すたびに難度表は無効になる、という前提で回すのが正しい
- 初期メンバーが終盤で編成から落ちる問題は、レベル上限の引き上げではなく
  **一度きりの解放**（進化）で解いた。連続量を伸ばしても「一段変わった」感触は出ない

### M3-2b — 衣装 ✅

- ⑨衣装（アイドルごと 4 スロット + セット効果 5 種 + 強化 +0〜+15 + 錬成 + 衣装画面）
- ライブのリザルトでドロップ（負けても 1 着）。乱数の状態はセーブに持つ

**やったこと / 分かったこと**:

- 設計に書いた効果のうち 2 つは**存在しない機構**を指していた（「効果命中」「Break」）。
  数値だけ実装しても効かないので、実在する機構へ読み替えて
  [03 ⑨](./03-progression.md#-衣装装備) に対応表を残した。
  設計書を書いた時点と実装の語彙がずれるのは避けられないので、
  **消すのではなく読み替えを記録する**
- 経済とグローバルの効果（開始時声援など）は per-idol にできない。
  合算にすると「全員に同じセット」が常に最適になるので、**編成内の最大値**にした
- 実測では、衣装フル（UR+15）は才能ボード 1 ブランチと同程度の上げ幅
  （S6 で観客 70 → 94）。恒久強化の到達点として妥当な位置に収まっている

## M4 — 周回（強化 P2）✅

- **★難度 1〜10**。HP・DEF・出現密度の 3 軸に分散し、★7 以降は系統ペナルティが巡回する
- **ステージ 8〜10**（冬の武道館 / 雨のアリーナ / 満月のドーム）と**ボス 2 種**
- ⑫プロデューサーランク（1〜50、才能ポイント +2/Lv）
- ⑩楽曲レベル（1〜15、ソロパートの解禁）
- ⑪ユニット絆 → ④フォーメーションのタグ条件として実装済み（M3-2）
- リザルトの貢献度グラフ

**受け入れ条件**: 20 時間プレイしても伸びしろが残っている。

**やったこと / 分かったこと**:

- **設計の「★7 以降は係数を下げる」は不要だった。** 追加ルール（系統 -20%）の
  実効寄与は編成全体で -7% 程度で、割引を入れると ★10 の要求戦力が
  60 倍 → 46 倍まで落ちてしまう。実測（`scripts/star-curve.ts`）で確かめて
  割引を撤回し、02-core-battle.md 2.10 に測定値を残した
- **ボスは leak を重くしないとボス戦にならない。** 設計値（20 / 25）だと
  倒せなくても素通しさせれば完走でき、「HP の大きい邪魔な敵」で終わっていた。
  45 / 40 にして、1 体通すと観客が半分近く飛ぶ形にした
- **ボスを本編の前提にしない。** 解放条件を「並び順のひとつ前」から導いていたので、
  B1 を挟むと S7 が開かなくなった。`stageUnlock` に明示の表を置いて分岐にした
- 才能ポイントをランクが配り続けるので、ボードの「全部は取れない」は
  **序盤だけの制約**になる。終盤で選ばせるのはキーストーンの排他

## M5 — 仕上げ（強化 P3 + 演出）

**着手済み: 登場人物の追加（12 人）と隠しキャラ**

- 一次情報で確認できた登場人物を全員実装した（諌山 真実・犬DOGE・FUSHI）。
  系統は 歌 4 / ダンス 4 / ヴィジュアル 4、コスト帯は 20〜80 で重複なし
- **名指しの相性**を足した。タグは「同じ組」という対称な関係しか表せないが、
  原作には片側だけのマイナスの相性がある（FUSHI はかぐやと犬DOGE に敵対的）。
  これが「置きたいけれど、かぐやの隣には置けない」という他の誰にも作れない問いになった
- 人型でない 2 体（犬・ウミウシ）はドット絵のリグから分けた。
  人型のリグへ通すと 2 体とも「獣耳の女の子」になり、原作と食い違う
- **隠しキャラ MASA**（リポジトリ所有者本人。原作外の唯一の例外）。
  解放はステージクリアではなく、**合言葉**または **S5 を ★5 で勝つ**の 2 経路。
  バランスの基準（参照盤面・CI の難度検証）からは外し、
  「外れていること」自体をテストで固定した
- 隠しキャラの鍵に**腕前の経路を後から足した**。合言葉だけだと、知らない人には
  ゲームでいちばん強い駒が永久に存在しないことになる。★5 は実測で
  「才能フル + Ray 進化」がちょうど届く位置（04-content.md）。
  代償として、そこから先は MASA を置いた盤面に難度が残らない —— 仕様どおりだが、
  難度曲線を守りたければ「MASA 抜きの記録」を別に持つ必要がある


- ✅ ⑥コール&レスポンス、⑬称号・実績（初期 30 種）、アクセシビリティ設定一式（M5-1）
- ✅ 月の都の章（ステージ 11 本・敵 12 種・敵のドット絵）（M5-2）
- ✅ 原作準拠の見直し（楽曲名・ステージ名・関係性・原作ネタ）（M5-3）
- ✅ 羽衣の章（ステージ 11 本・敵 9 種・盤面テンプレート 4 種）（M5-4）
- ✅ BPM 同期の BGM 合成、SE、カットイン演出、才能ボードの拡張（M5-5）
- ✅ ツクヨミの空と原作の呼称（ミラーボール・魚群・ヤチヨカップ・卒業ライブ）（M5-6）

- ✅ オンボーディングの段階解放、チュートリアル（M5-8）

**受け入れ条件**: 初見プレイヤーが説明なしでステージ 3 まで到達できる。

### M5-8 —— 段階解放とチュートリアル ✅

**やったこと / 分かったこと**:

- **新規プレイヤーのホームは「ライブ」1 つだけになった。** 前は編成・才能ボード・
  衣装・称号・育成・ライブが最初から全部並んでいて、1 本目の前に
  6 つの系統を見せていた。強化系統が多いのは中核なので、減らすのではなく順に開く
- **解放の順は設計ではなく実測で決め直した。** 表は「セットリストは S2 クリア、
  月華は S3 クリア」だったが、測ると **S3 は月華が無いと勝てない**
  （Lv5・フル配置で 3/5 → 1/5）。表のとおりに塞ぐと、ちょうど難しくなる回で
  最も強い手札を取り上げることになっていた。逆に S1・S2 は両方塞いでも 5/5 なので、
  1 本ずつ前倒しした ―― 「1 ステージにつき新しい仕組みは 1 つ」は保ったまま
- **sim を塞ぐ既定は「塞がない」。** `BattleMeta.locked` を省略すると全部使える。
  ここを既定で塞ぐと、34 ステージぶんの `hpMul` 実測が全部やり直しになる。
  塞ぐかどうかを決めるのは meta 層で、sim は渡されたものを受け取るだけ
- **覚醒分岐は塞がなかった。** 参照盤面（`balance/plans.ts`）が `awakening` を
  使っているので、塞ぐと S1〜S3 の難度が変わる。その場で出てくる選択なので、
  出た瞬間に説明すれば足りる
- **隠すだけだと進行が止まったように見える。** 「◯◯（S5）をクリアすると
  才能ボードが開きます」を 1 行、リザルト直後に「新しく開きました」を 1 枚
- **説明する対象に説明が覆われていた。** チュートリアルの札を下部バーの中に
  置いていたら、セットリストの選択（全画面のオーバーレイ）に隠れて
  「わかった」が押せなかった ―― よりによって、そのオーバーレイを説明する札が。
  実機で新規セーブから通してみるまで気づかなかった
- **すでに遊んでいる人には出さない。** 1 本でもクリアしているセーブは
  移行の時点で全部の札を「見せ済み」にする。配置も強化も通ってきた人に
  いまさら「まずは配置」を出すのは失礼なうえ邪魔になる

### M5-7 —— BGM を「曲」にする ✅

**やったこと / 分かったこと**:

- **決定的なのと音楽なのは別。** 最初の実装は音階の音をハッシュで選んで並べていた。
  乱数を避けたので毎回同じには鳴るが、それは「同じでたらめ」であって旋律ではない。
  曲ごとの違いも調と打ち方だけで、**7 曲が実質同じ曲**だった
- **記憶に残る旋律を作るのは、繰り返しと変形。** 曲ごとに 3〜5 音の**動機**を持たせ、
  移高・反行・逆行・拡大・縮小・断片化で展開する（`audio/motif.ts`）。
  クラシックの主題労作と同じ道具立てで、手続き的な生成でもここが中心になる。
  動機が違えば別の曲になる —— 調を変えただけの 7 本にはもう戻らない
- **原曲のオルゴール版は作れない。** 音源を使わなければいいという話ではなく、
  旋律を打ち込みで再現すること自体が楽曲の複製・翻案にあたる。
  借りられるのは**音色のほう**だったので、オルゴールの声部を足して
  イントロと間奏をそこに任せた（倍音が整数比から外れる金属の音は、
  加算合成で近似できる）
- **5 音音階に三和音を積むと濁る。** 和風の定番どおり**四度堆積**にした。
  5 音音階では「1 つ飛ばし」がほぼ 4 度になるので、度数 +2 ずつ重ねるだけで済む
- **変形の倍率を直に書くと譜面が壊れる。** ×1.15 のような倍率は、
  動機の長さが曲ごとに違うぶん 0.575 拍や 0.1 拍を生む。
  小節の終わりに残る 0.1 拍は、旋律ではなく**取りこぼし**に聞こえた。
  倍率ではなく**行き先の拍数**で指定する形にして、16 分の格子に乗せた
- **正しい仕組みを足し合わせると音域が上がり続ける。** 進行で根音が上がり、
  セクションでオクターブが乗り、終止で主音へ跳ぶ —— それぞれは正しいのに、
  サビの終わりが 3 オクターブ上（MIDI 88）まで飛んでいた。
  高い和音は**転回して主音の近くへ寄せ**、終止は音域から外れるなら
  反対側の主音で終える。畳んで受けると楽句まるごと動いて、最後の小節だけ急に低くなる
- **「AudioContext が running」は鳴っている証拠にならない。** destination へ
  繋がれた音を横取りして波形を測るところまでやった（イントロ −17dBFS、
  サビ −6dBFS、クリップなし）。前回 Safari で鳴らなかったのを見落としたのと同じ種類の穴

### M5-6 —— ツクヨミの空と原作の呼称 ✅

**やったこと / 分かったこと**:

- **背景がいちばん長く目に入る。** ステージ名を原作へ寄せたあとも、
  空には普通の月を描いていた。原作のツクヨミの空にあるのは
  **月の代わりの巨大なミラーボール**で、色とりどりの魚群・飛行船・
  空を飛ぶ蒸気機関車が行き交う。名前をいくら原作から借りても、
  見えている空が違えばその世界にはならない —— ステージ名で一度やったのと同じ失敗を、
  背景でもう一度やっていた
- **本物の月は第 2 章から昇らせた。** ツクヨミの空にあるのはミラーボールだけ。
  月が大きくなっていくのは、月の都が迎えに来てからでいい。
  「迫る期限を言葉なしで伝える」という当初の意図は、章の進行に紐付けたほうが効く
- **章にも原作の呼称があった。** 第 1 章は「ヤチヨカップ」——
  1 か月でいちばん新規ファンを獲得したライバーがヤチヨとのコラボライブの権利を得る大会で、
  かぐやはこれでデビューする。麓から天守までの道のりが、そのまま大会だった。
  最終ステージも「卒業ライブ」という名前が原作にある
- **設計書の表が実装から取り残されていた。** 第 1 章のステージ表に
  「テレビ局スタジオ」「冬の武道館」が残っていた（実装では M5-3 で直したもの）。
  データを直したら表も直す
- **結末に関わる設定は使わない。** 調べると本編の核心に触れる説明が出てくるが、
  一次情報で裏が取れないうえ、ファン制作物が結末を先に見せるのはおかしい。
  FUSHI の正体と同じ扱いで、**あらすじの範囲まで**にした

### M5-5 —— 音とカットイン、才能ボードの拡張 ✅

**やったこと / 分かったこと**:

- **音源を置けないなら、コードで曲を組み立てればいい。** ドット絵と同じ方針。
  和の響きを決めているのは音色ではなく**音階**なので、都節・律・陰旋で書けば
  単純な波形でも和に聞こえる。逆に長音階のままだと、どれだけ音色を寄せても
  「和風の音がする洋楽」にしかならない
- **譜面と発音を分けると、音を聞かずにテストできる。** `compose.ts` は
  Web Audio を知らないので、「サビで太鼓が鳴っているか」「イントロが静かか」
  「毎回同じ曲になるか」を CI で見張れる
- **音が時刻を持ってはいけない。** `AudioContext.currentTime` は一時停止でも
  選択中でも止まる。sim の時計に追従させ、1 小節先まで予約する形にした。
  倍速は「速く弾く」で表すので、録音の早回しと違って音程が上がらない
- **ポイントでは終盤の選択を作れない。** 才能ポイントの供給は最大 233 pt。
  ボードをどれだけ広げても追いつかず、追いつかせようとすると今度は
  参照盤面との差が開きすぎて難度表が意味を失う。上限は**排他**で決めた ——
  最終才能をボード全体で 1 つだけにして、そこに選択を残している
- **ダメージを消す特性と同じで、演出も「濃度」の設計が要る。**
  カットインは同じ種類を上書き、控えは 1 つまで。列を作ると、
  盤面が動いているのに数秒遅れの通知が流れ続ける
- **最小設定でも情報は消さない。** カットインは点滅ではなく情報なので、
  消すと「ボスが湧いたのに気づかない」が起きる。長さだけを落とす

### M5-4 —— 羽衣の章（ステージ 11 本 + 敵 9 種 + 盤面 4 種）✅

**やったこと / 分かったこと**:

- **恒久強化の段階は 4 つで打ち止め。** 第 3 章の前提は衣装 UR+15（`max`）で、
  これが 03-progression.md E-2 の到達点そのもの。**これ以上の前提は置けない** ——
  置いたら「遊べば届く範囲」の外になる。次に難度を足すときは、
  前提ではなく**盤面の形か敵の問い**を変えるしかない
- **一本道の盤面は「観客が減って負ける」にならない。** S24 を経路長 63 マスの
  一本道で作ったところ、どの `hpMul` でも観客が 1 も減らなかった。
  被弾回数が多すぎて**必ずゴール前に落ちる**ので、負けるのは
  「計測上限の 10 分までに倒し切れなかった」ときだけ。勝敗が観客ではなく
  上限時間で決まるステージは、遊ぶ側から見て何が起きたのか分からない。
  3 本の「潜り」（1 レーン 19 マス）に置き換えて、負け方を観客に戻した
- **ダメージを消す特性は、強化の段階も一緒に消す。** `link`（守り手がいると 80% 軽減）を
  全レーンへ厚く撒いた S27 は、衣装を積んでも積まなくても同じ結果になり、
  段階の差が測れなくなった。**織り手は常に 1 レーンだけ**に絞って解決している。
  倍率で潰す特性は「濃度」まで含めて設計しないと、成長そのものを無効化する
- **バリアに吸われたぶんは貢献度にも月華にも数えない。** 数えると
  「割れないバリアを叩き続けるのがいちばん稼げる手」になり、
  「守りを剥がしてから殴る」という問いがそのまま逆立ちする
- **盤面テンプレートを 4 つ足した**（二重合流 / 交差 / 潜り / 二又）。
  レーン数を増やすのは第 2 章でやり切ったので、**形のほうで判断を変える**。
  「潜り」はレーンが一段沈んでまた戻るので、他の盤面が
  「どのレーンを見るか」なのに対して「1 本を何回見るか」になる

### M5-3 —— 原作準拠の見直し ✅

**やったこと / 分かったこと**:

- **名前を作る前に原作を調べ直すべきだった。** 楽曲名（カグヤ・ライジング、
  ネオン蓬莱…）もステージ名（テレビ局スタジオ、冬の武道館）も本作の創作で、
  原作にはまったく関係が無かった。**原作は「ボカロ P が書き下ろした劇中歌」で
  成り立っている作品**なので、曲名を差し替えていたのはいちばん重要な部分を
  別物にしていたということ
- **世界観の穴は名前より深いところにあった。** ツクヨミは
  「丘状の陸地、最上層にヤチヨ城、常に夜」。現実の会場名を並べていた時点で、
  どれだけ和風の言葉を選んでも原作の外の話になっていた。
  本編を**麓から天守まで登る道のり**に組み直した
- **原作の地の言葉は「配信」だった。** セットリストのカードが
  「発声練習」「ダンスシューズ」というアイドル研修の語彙だったのを、
  スパチャ・切り抜き師・同時接続・子ウサギ大集合へ寄せた
- **関係性はタグと二重に乗る。** 百合を含む人間関係を相性として足したら、
  かぐや×彩葉 の攻撃速度が 1.1 ではなく **1.21** になった。ユニットタグが
  同じ +10% をすでに配っていたため。**タグが配っていない軸（攻撃力）だけを
  相性に書く**規則にして、テストで固定した
- **音源は使えないが曲名は使える**、という線引きを設定画面に書いた。
  楽曲の著作権と録音の著作隣接権は別物で、後者があるかぎり音源は同梱できない。
  曲名だけを借りて音は合成する形にしたので、**その 1 点は必ず読める場所に置く**

### M5-2 —— 月の都の章（ステージ 11 本 + 敵 12 種 + 敵のドット絵）✅

**やったこと / 分かったこと**:

- **レベル上限の先にコンテンツを足すと、難度の測り方が変わる。** S10 の時点で
  レベルは上限（30）。そこから素の値で難度を上げると「上限まで育てても勝てない壁」に
  なるので、参照盤面に**恒久強化の仮定**を持たせた（`balance/plans.ts` の `Investment`）。
  検証も「Lv いくつで届くか」から**「その段階なら届き、ひとつ手前では届かない」**へ変えた。
  実測 5 シードで、11 ステージすべてが 5/5 対 0/5 に分かれる
- **敵を丸から絵にした。** 9 種のうちは色と大きさで足りていたが、23 種では
  役割の違いが見えない。ノイズは抽象的な形（露は雫、鏡は六角）、竹取物語の
  登場人物は人型で描き分ける。属性は絵ではなく**足元の光**で示す ——
  絵の色を属性に合わせると、五人の貴公子を塗り分けられなくなる
- **新しい特性は「答えを潰す」ために置いた。** `typeGuard`（その系統では通らない）、
  `enrage`（削りかけを罰する）、`revive`（瞬間火力だけでは足りない）。
  ただし `typeGuard` は Echo には掛けない —— 全経路に掛けると
  「その系統を外す」以外の答えが無くなり、問いではなく禁止事項になる
- **副作用を 1 つ作った。** ステージが 12 → 23 本でポイント供給がほぼ倍になり、
  才能ボードが終盤で埋まりきる（59/60 → 92/60）。ボードを伸ばすのが素直だが、
  `fullBranch` が変わると第 2 章の `hpMul` を全部測り直すことになるので保留。
  `talents.test.ts` に「これは想定どおりで、同時に宿題」と書いて残した
- **五つの難題は「原典の失敗のしかた」をそのまま能力にした。** 石作皇子は
  偽の鉢（撃破で湧く）、車持皇子は工匠が押しかける、阿倍御主人は焼けない、
  石上麻呂は落ちる。数値を割り振るより先に**何の話だったか**から決めると、
  敵ごとの問いが自然に別物になる

### M5-1 —— コール & レスポンス / 称号・実績 / 設定 ✅

**やったこと / 分かったこと**:

- **2.9 と 6.7 は正面からぶつかっていた。** 2.9 は「上手い人が 10〜15% 得」と言い、
  6.7 は「コール OFF でも有利不利を実質ゼロ」と言う。**6.7 を優先**した ——
  リズム入力ができない人が、それだけの理由で不利になるのは避ける。
  結果として「押す得」は Perfect と Good の差ぶんに縮み、実測で観客 +6〜15 点に収まった
- **コールの得は撃破数でも与ダメージでも測れなかった。** どちらも敵の総数・総 HP に
  張り付く。最初の計測は +0.3%（ほぼ無意味）と出て、しきい値の二分探索では
  **−12%（入れると弱くなる）** という逆の結論まで出た。
  勝敗が段差で決まるので二分探索が非単調になる、という M4 の B2 と同じ罠
- **自動 Good ぶんで難度表が動いた。** 小節ごとに月華が増えるので全体が易しくなり、
  S5 / S7 / B2 を上げ、B1 は下げた（B1 だけ「ボスが 1 体漏れる」段差に張り付いて
  Lv1 も Lv30 も観客 55 になっていた）
- **実績はセーブに解除済みを持たない。** 才能ポイントと同じで、条件を変えたときに
  古いセーブだけ食い違う。持つのは進捗から導けない生の記録だけ。
  資金だけは残高が増減するので受領済みを別に持つ
- 設定の既定はすべて「誰でも遊べる側」。設定画面を開かないまま遊ぶ人がいちばん多い

**レビュー後に直したこと**:

- コールの窓を**小節の頭より 160ms 手前から**開くようにした。境界のフックで
  開けていたので、早押しが丸ごと弾かれて ±160ms が片側だけの窓になっていた
- 演出強度を門ではなく**振れ幅**として使うようにした。「控えめ」でも
  標準と同じ閃光が出ていて、光過敏対策の意味が無かった
- Space は盤面にフォーカスがあるときだけコールへ回す。ボタン上で奪うと
  キーボードだけで遊ぶ人が何も押せなくなる
- 実績「本編制覇」がボスステージを数えていた（B1 を挟むと S10 未クリアで達成）。
  「全員集合」は隠しキャラを数えていた（GM を出すだけで達成）

**後から足した 3 人の底上げ**（配置コストは据え置き）:
初出時は 3 人とも同系統で最下位付近だった。真実 0.85→1.24 /
犬DOGE 3.65→5.51 / FUSHI 0.93→1.23（コストあたりの毎秒期待値）。
真実は半径も広げたら**全 12 人中トップ**になったので半径は戻した ——
範囲は面積で効くので、火力の底上げと重ねると乗算になる。

## リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| 強化系統が多すぎて調整不能になる | 致命的 | `modifiers.ts` への一元化 + CI バランス検証（M3 で導入）。系統追加は必ずシミュレータ検証とセット |

| Canvas 2D の描画限界 | 中 | `render/` を差し替え可能な抽象にしておき、必要なら PixiJS(WebGL) へ移行 |
| アセット制作がボトルネック | 中 | 暫定図形で先に検証。エフェクト優先の方針でキャラ枚数依存を下げる |
| 音源の権利 | 中 | 手続き生成 BGM を既定にし、外部音源は差し替え可能な扱いに留める |
