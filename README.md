# IDOL DIFFENCE

アニメ映画『**超かぐや姫！**』の非公式ファン制作タワーディフェンス。

仮想空間 **ツクヨミ** のライブ会場に湧く「ノイズ」を、**歌・ダンス・ヴィジュアル**で退け、
ライブを完走させる。**かぐや（歌）/ 酒寄 彩葉（ダンス）/ 月見 ヤチヨ（ヴィジュアル）** から始まり、
ステージを進めると Black onyX の 3 人やツクヨミのライバーたちが加わって全 12 人になる。
**登場人物はすべて原作の人物**で、本作でキャラクターを作り足すことはしていない。
育成画面では一人ずつの**由来**も読める（かぐやとヤチヨが同じ人であること、
犬DOGE と FUSHI が同じ個体であることも含む —— **本編の核心に触れます**）。

**遊べます → https://masaspc.github.io/IdolDiffence/**

**現在のステータス: M5-21 完了** —— ステージ **34 本**（うちボス 4 本）、
**原作の登場人物 12 人**（+ 隠しキャラ 1 人）、敵 **32 種**、楽曲 7 曲、実績 30 種。
ステージは仮想空間**ツクヨミ**の中だけを舞台にし、麓の路地裏から**ヤチヨ城の天守**まで登ります。
第 1 章は原作の「**ヤチヨカップ**」（いちばんファンを集めた人がヤチヨとコラボライブ）、
空には月ではなく**巨大なミラーボール**が浮かび、魚群と飛行船と蒸気機関車が飛び交います。
楽曲名は**原作の劇中歌**（Reply / ray 超かぐや姫！Version / 星降る海 ほか）。
S11 以降は**竹取物語をなぞる第 2 章**で、五つの難題と月の都の迎えが敵として登場し、
S21 以降の**羽衣の章**では月の都の内側と、着せられれば全部忘れる一枚の衣が相手になります。

起動すると**タイトルからツクヨミへ「接続」**して入り、ホームでは
主題歌 Ex-Otogibanashi の枠に紐付けた**本作オリジナルの旋律**がオルゴール風に流れます
（原曲のオルゴール編曲ではありません —— 旋律の再現も権利上できないため）。
ホームのステージ一覧は**配信アプリの枠一覧**（配信予定／初配信／アーカイブあり）で、
バトル中は**視聴者コメント**（かぐやっほ～！／ヤオヨロー！）が画面上端を流れ、
月華や完走の盛り上がりでは**スパチャ**（色付きカード + 金額）になり、
センターステージの前には**子ウサギの客席**（かぐやのファンネーム）が同接に合わせて埋まり、
サビではペンライトが一斉に色を替えます。
守っているゲージの数字も**同接**と呼びます —— 守っているのがライブ配信であることが
画面から分かります。
BGM は曲ごとの**動機を移高・反行・逆行で展開する**手続き合成で、音色は
**弦の物理モデル（Karplus-Strong）や膜の振動モード**から波形を計算しています ——
原作の音源・旋律は一切使っていません。

> **流れている音は本作が合成したオリジナルです。** 和楽器をシンセで近似して、
> ステージの BPM と構成に合わせてその場で組み立てています。曲名と作曲者・歌唱は
> 原作へのクレジットで、**原作の音源は使っていません**。
> 原作の曲は Netflix と各配信サービスで。
配置・ポジション強化（6 段階）・覚醒分岐・セットリスト・フォーメーション・
才能ボード（54 ノード・**最終才能はボード全体で 1 つ**）・
衣装・進化（Ray）・月華の解放・育成・編成・センター・★難度 1〜10・
プロデューサーランク・楽曲レベル（ソロパート）・**コール & レスポンス**・
**称号と実績**・**アクセシビリティ設定**・**BGM と効果音**・**カットイン**が動作します。

## 開発

```bash
npm install
npm run dev            # 開発サーバー
npm test               # 単体テスト
npm run lint           # 決定性ルールを含む Lint
npm run typecheck      # 型チェック
npm run validate:data  # ゲームデータの検証
npm run build          # 本番ビルド
```

### バランス計測

数値は感想ではなく実測で決めています。

```bash
npx tsx scripts/probe.ts                 # 全ステージ × 育成レベルの結果一覧
npx tsx scripts/sweep-difficulty.ts S5   # 採用した hpMul の周辺を掃く
```

参照盤面は `src/balance/plans.ts`。境界は `src/balance/balance.test.ts` が CI で見張ります。

### 実装済み（M0〜M3-1）

| モジュール | 内容 |
|---|---|
| `src/core/loop.ts` | 固定タイムステップ 1/60 秒 + 描画補間。実時間に触れてよい唯一の場所 |
| `src/core/clock.ts` | `GameClock` — sim 時刻の唯一の源。BPM / 拍 / 小節、ポーズとカード選択時のスナップ |
| `src/core/rng.ts` | seed 付き PRNG（mulberry32）。`Math.random()` は Lint で禁止 |
| `src/core/events.ts` | 型付き EventBus |
| `src/core/vec.ts` | ベクトル演算（アロケーションを避ける out 引数方式） |
| `src/sim/world.ts` | バトル状態。DOM 非依存で、React はスナップショットを読むだけ |
| `src/sim/modifiers.ts` | 強化の合流点。加算プール / 乗算プール / 定数加算を分離 |
| `src/sim/systems/` | 移動・戦闘・スポーン・ターゲティング・カード |
| `src/render/renderer.ts` | Canvas 2D。静的レイヤをオフスクリーンにキャッシュ。縦画面では盤面を 90° 倒す |
| `src/render/sprites.ts` | 配置メンバーのドット絵をコードで生成（差し替え可能な `SpriteProvider`） |
| `src/data/` | JSON + Zod スキーマ。ビルド時に検証 |
| `src/meta/` | セーブ（マイグレーション付き）・育成・才能ボード・進化・衣装・ランク・楽曲レベル・隠し要素・実績・設定 |
| `src/ui/idolText.ts` | 能力の説明を**数値から導く**。JSON に説明文を持たせない |
| `src/sim/star.ts` | ★難度。HP・DEF・出現密度の 3 軸に分散させる |
| `src/balance/` | 参照盤面とバランスの CI 検証 |

## 特徴

- **3 系統の攻撃**: 歌（範囲・持続）/ ダンス（単体・機動）/ ヴィジュアル（妨害・支援）の 3 すくみ
- **楽曲がウェーブ**: イントロ → A メロ → B メロ → サビ。BPM に同期して敵が湧き、サビで演出が加速
- **月華ゲージ**: 溜め切ると全員のスペシャルライブが炸裂
- **強化が満載**: 1 プレイ内で完結する強化と、積み上がる恒久強化の二層構造
- **編成とセンター**: 原作の 12 人から 5 人を選び、1 人をセンターに。センターは全体パッシブを供給する
- **原作の関係が配置になる**: 犬DOGE はかぐやの隣で速くなり、FUSHI はヤチヨの隣で本領を出すが
  かぐやと犬DOGE の隣では機嫌が悪くなる（**それが昔の自分だから** ——
  「犬ころめ！いい気になるなよ！」）。人型でない 2 体は専用のドット絵で描く
- **敵が問いを出す**: 高 DEF・飛行・回復・分裂・前面シールドなど、それぞれ別の答えを要求する
- **ボス 2 種**: 「偽アカウント」は属性が 3 すくみを一周し、「強制ログアウト」は
  1 レーンを 4 秒沈黙させる。どちらも数値ではなく**編成と配置**を問う
- **★難度 1〜10**: HP だけでなく DEF と出現密度にも分散。★7 以降は系統ペナルティが巡回し、
  ★10 の要求戦力は ★1 の約 60 倍（恒久強化の到達点と一致させてある）
- **押しても押さなくてもいい**: サビ中のコール & レスポンスは任意参加。切ると Good 相当が
  自動で入るので、リズム操作が苦手でも不利にならない（既定はオフ）
- **アクセシビリティ**: 演出強度 3 段階（光過敏対策）、文字サイズ 3 段階、
  敵の属性を色以外でも示す記号、フルキーボード操作
- **ツクヨミが舞台**: 和風建築にネオンを重ねた仮想空間のライブワールドを守り抜く
- **縦持ちスマホ対応**: 縦画面では盤面を 90° 倒して画面いっぱいに使い、HUD は 1 行ぶん畳む
- **ドット絵はコード生成**: 画像ファイルを持たず `src/render/sprites.ts` が 48×48 の
  スプライトを組み立てる。手描きに差し替えるときは `SpriteProvider` を渡すだけ
- **初期メンバーが最後まで使える**: かぐや / 彩葉 / ヤチヨ は劇中歌にちなんだ
  **(Ray) バージョン**へ進化し、火力も見た目も一段変わる
- **衣装はハクスラ**: アイドルごとに 4 スロット、竹取物語の五つの難題にちなんだ
  セット効果、強化 +15、錬成。ライブのリザルトで落ち、**負けても 1 着は出る**

## 配信

サーバー不要のクライアント完結構成のため、GitHub Pages で配信します。
`main` への push で [`.github/workflows/deploy.yml`](./.github/workflows/deploy.yml) がビルドとデプロイを行い、
`https://masaspc.github.io/IdolDiffence/` に公開されます。

### 初回のみ必要な手動設定

**リポジトリ設定 → Pages → Build and deployment → Source を「GitHub Actions」に切り替える。**

これを済ませるまで、ワークフローは `actions/configure-pages` の段階で失敗します
（`Get Pages site failed ... Not Found`）。ビルドは成功しているので、設定後は `main` へ
何かを push するか、Actions 画面から Deploy ワークフローを再実行すれば公開されます。

`configure-pages` の `enablement: true` で自動化を試みましたが、ワークフローの
`GITHUB_TOKEN` には Pages サイトの**作成**権限が無く
（`Create Pages site failed. Error: Resource not accessible by integration`）、
リポジトリ管理者による一度きりの手動操作が必要です。

Pages 固有の注意点は [05. 技術アーキテクチャ 5.10](./docs/design/05-architecture.md#510-配信--デプロイgithub-pages) を参照。
